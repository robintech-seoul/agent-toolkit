MVP 파이프라인을 시작한다 (v4).
`--lite` 를 붙이면 **가벼운 스킬 모드**로 돈다 — agent-skills 양식 대신 단계별 기본 프롬프트(스펙·설계·리뷰·계획·구현,
각 100~230단어)만 붙는다. 게이트·루프·원장은 동일. 작은 프로젝트(단일 파일 앱·CLI·게임 한 판)에 맞다.
기본(`--full`)은 플러그인 안에 내장된 agent-skills 를 쓴다 — 외부 플러그인 설치가 필요 없다.
`--mode design` 을 붙이면 **하이레벨 설계 모드**로 돈다 — 큰 프로젝트를 모듈·기능 정의(스펙)
→ 설계·리뷰 루프 → 「하위 프로젝트 분해」까지만 진행하고 `designed` 로 종결한다.
분해표의 idea 한 줄들이 이후 개별 실행의 입력이 된다. 구현 단계는 돌지 않는다.
`--fast` 를 앞에 붙이면 속도 프로필로 돈다 — 낮은 모델·노력과 줄인 라운드 예산으로,
가벼운 프로젝트를 품질 일부와 맞바꿔 빠르게 만든다. 프로필 정의는 `policy/profiles.tsv`.
(설계 모드는 이후 모든 실행의 계약을 만드므로 기본 프로필(standard)을 권장한다.)
`--auto-approve` 를 붙이면 **자동 게이트**로 돈다 — 기계 게이트를 통과한 단계(스펙: 수용 기준 1건 이상,
설계: 반영률 통과 + 리뷰 must 0)는 스스로 승인해 구현까지 한 번에 간다. 미통과·판정 불가는 사람 승인 대기로
떨어진다. 무인 실행용이며, 한 커맨드 안에서 전체가 돌므로 시간이 걸린다. 진행은 `/mvp-builder:status` 로 본다.

!`bash "${CLAUDE_PLUGIN_ROOT}/bin/phase-spec.sh" $ARGUMENTS`

위 결과를 사용자에게 정리해 전달해라. SPEC.md 의 수용 기준 개수와 주요 항목을 요약해라.
게이트가 human(기본)이면 **승인 없이는 다음 단계로 넘어가지 않는다**는 것을 알려라. 사용자를 대신해 승인하지 마라.
게이트가 auto(`--auto-approve`)이면 어느 단계가 어떤 근거로 자동 통과됐는지(수용 기준 수·반영률·must)와
최종 상태(`built` 또는 보류된 게이트)를 보고해라. 보류됐다면 사람 승인이 필요하다는 것을 알려라.
